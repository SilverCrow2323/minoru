# Language policy — Minoru⁶

This project deliberately mixes two languages. Here's the rule, so nobody
"fixes" it by accident:

## English — code, comments, docs, CHANGELOG, commit messages

The library is meant to be embedded in *other people's* LÖVE programs.
Code that talks to other developers is English, full stop. This includes:

- every `.lua` file's comments and identifier names
- `README.md`, `CHANGELOG.md`, `NOTICE.md`, this file
- GitHub commit messages and release notes
- error messages returned from the library (they may end up in a host
  program's logs, so they must be readable by everyone)

## Italian — the demo dialogue, and only the demo dialogue

Minoru⁶ is an Italian character. His canonical voice (as defined in the
I.R. dossier) is *Sarcasmo Elicoidale* — sarcastic, ironic, that specific
Italian register that doesn't survive translation. When Minoru speaks
in `main.lua`'s `REACTION_KEYS`, he speaks Italian. That's not a bug,
that's the character.

The library itself (`minoru/*.lua`) contains **no** hardcoded dialogue.
Every line Minoru says comes from whoever embeds him. If you want an
English-speaking robot companion for your own game, use your own lines.

## What this means in practice

- If you're translating the demo: don't. The demo is a *voice sample*.
- If you're embedding Minoru: your game's language, your dialogue.
- If you're reading the code and see Italian in `main.lua`: it's the
  demo's script, not a localization oversight.

## Why not full i18n in the library?

Because the library has no strings to localize. The only user-facing text
is what the host program passes to `mo:say(...)`. Adding a translation
layer for zero strings would be cargo-culting.

If a future version ships *built-in* strings (default greetings, error
voice lines), *then* an i18n module becomes justified. Not before.
